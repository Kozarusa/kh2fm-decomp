## What is proved, and what remains inference

Independently rechecked the seven saved verification JSON files: each saved source SHA256 matches its proof; compiled bytes equal the corresponding original ELF slice at the complete target size (88,108,88,108,108,108,108 bytes). Current accepted source text equals the corresponding proved candidate after whitespace removal. This is existing-proof verification, not a new compilation of accepted files. Exact machine code is established for those candidates.

Exact bytes do not establish that a C++ function must semantically return every incidental value left in the ABI return register. A compiler can leave scratch/pointer/predicate state in v0 for a genuine void function. Conversely, a void source declaration does not expose a result to a source-level caller even when its current machine code leaves that register unchanged. No caller-use analysis, original debug signature, authoritative callback prototype, or new return-typed candidate was established in this audit. Signedness and width also need independent ABI evidence; observing v0 alone does not choose u32 versus s32 versus pointer or broader integer transport.

Therefore the concrete defect demonstrated here is inconsistent enforcement of an explicit conservative recovery policy, not proof that seven original functions had non-void high-level signatures or that accepted binaries malfunction. 00242c00 has especially strong policy evidence because all final direct callees are already typed u32, but that remains an inferred source contract.

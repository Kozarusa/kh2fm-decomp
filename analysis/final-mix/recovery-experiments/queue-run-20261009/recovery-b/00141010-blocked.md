# 00141010: native address scheduling and float lifetime

Original range is 96 bytes in live layout. The archived v4_1 proposal differs only in the first conditional branch and its address setup: the hand-written LUI moves before the branch and the low-address addiu occupies its delay slot. The original places the LUI in the delay slot.

Twelve new isolated variants remain nonmatching. Clobbering return registers in the LUI assembly grows output to 100 bytes; adding condition dependence or memory clobber grows to 104 bytes. A useful new result is compiler-native `high=0x350000` with an input-only empty register marker (nativehighinput): it reproduces the original first conditional branch and LUI delay slot at offsets 0x18/0x1c, at the original total 96-byte size. However, compiler float and constant-address setup then hoists across the object check, changing later scheduling. The volatile native-high marker gives the same result. Read/write high markers grow output to 100 bytes.

Subsequent object-volatile markers and f14 clobbers change size to 100/108 bytes. An explicit object-dependent mov.s stays 96 bytes but does not match. All full proofs and failed sources remain preserved; 00141010-blocked-evidence.json binds source/proof hashes and full original range hashes.

Next hypothesis: start from nativehighinput, whose first branch is correct, and constrain the later argument-address and floating-point setup as one dependency chain after the object-check branch. Preserve compiler-native LUI generation for the first branch; do not revert to a hand-written LUI or repeat blanket f14 clobbers. This result narrows the problem to later lifetime scheduling; it does not prove compiler impossibility.
